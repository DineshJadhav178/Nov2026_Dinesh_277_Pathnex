# Day 08 – Apache Kafka Coding Practice

## 2. Start Kafka in KRaft Mode

**Objective:** Understand how Kafka works without ZooKeeper.

Tasks:

- Understand KRaft architecture.
- Learn the role of Kafka controllers.
- Understand metadata management.
- Explore broker and controller configuration.

For a local test environment, follow the official Kafka KRaft quickstart to generate a cluster ID, format the storage directory and start the server.

Typical commands in a configured Kafka installation:

```bash
# Generate a cluster ID
KAFKA_CLUSTER_ID="$(bin/kafka-storage.sh random-uuid)"

# Format Kafka storage using the configured server properties
bin/kafka-storage.sh format \
  --standalone \
  -t "$KAFKA_CLUSTER_ID" \
  -c config/server.properties

# Start Kafka
bin/kafka-server-start.sh config/server.properties
```

**Important:** These commands assume a compatible standalone KRaft configuration. Do not format an existing Kafka data directory without understanding the impact.

## 3. Create Your First Kafka Topic

**Objective:** Understand topics and partitions.

Create a topic:

```bash
kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create \
  --topic pathnex-events \
  --partitions 3 \
  --replication-factor 1
```

List topics:

```bash
kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --list
```

Describe topic:

```bash
kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --topic pathnex-events
```

Tasks:

- Create a Kafka topic.
- Understand topic names.
- Configure partitions.
- Understand replication factor.
- Observe partition distribution.

**Note:** Replication factor 1 is suitable for a single-broker local lab. For a multi-broker cluster, practice replication factor 2 or 3 where the number of available brokers permits it.

## 4. Produce Messages Using Kafka Producer

**Objective:** Send messages to a Kafka topic.

Run the producer:

```bash
kafka-console-producer.sh \
  --bootstrap-server localhost:9092 \
  --topic pathnex-events
```

Enter sample messages:

```text
Application started successfully
CPU utilization reached 80%
Memory utilization reached 75%
Application health check successful
Database connection timeout
```

Tasks:

- Produce multiple messages.
- Understand producer-to-broker communication.
- Understand message keys.
- Learn partitioning strategies.
- Understand producer acknowledgments.

Try producing messages with keys:

```bash
kafka-console-producer.sh \
  --bootstrap-server localhost:9092 \
  --topic pathnex-events \
  --property parse.key=true \
  --property key.separator=:
```

Enter:

```text
server-01:CPU utilization is high
server-02:Memory utilization is high
server-01:Application restarted
```

Observe how records with the same key are routed to the same partition under the default keyed partitioning behavior.

## 6. Kafka Consumer Groups

**Objective:** Understand parallel processing using consumer groups.

Start a consumer with a group ID:

```bash
kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic pathnex-events \
  --group pathnex-consumer-group
```

Open another terminal and start another consumer using the same group:

```bash
kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic pathnex-events \
  --group pathnex-consumer-group
```

Check consumer groups:

```bash
kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --list
```

Describe a consumer group:

```bash
kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --group pathnex-consumer-group
```

Tasks:

- Create a consumer group.
- Run multiple consumers in the same group.
- Understand partition assignment.
- Understand consumer parallelism.
- Understand consumer rebalancing.

**Important:** Within a consumer group, a partition is assigned to at most one consumer at a time. Additional consumers beyond the number of partitions may remain idle.

## 7. Understand Kafka Offsets

**Objective:** Understand how Kafka tracks consumer progress.

Commands:

```bash
kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --group pathnex-consumer-group
```

Understand these fields:

- CURRENT-OFFSET
- LOG-END-OFFSET
- LAG
- PARTITION
- CONSUMER-ID

Tasks:

- Understand what an offset represents.
- Learn automatic offset commits.
- Understand manual offset commits.
- Learn how consumers resume processing.
- Understand the impact of offset resets.

Practice inspecting offsets:

```bash
kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --group pathnex-consumer-group
```

Understand the difference between:

- `--to-earliest`
- `--to-latest`
- `--to-offset`

Do not reset offsets in a shared or production consumer group without approval.

## 9. Kafka Producer Acknowledgment Levels

**Objective:** Understand producer delivery reliability.

Learn:

**acks=0**
- Producer does not wait for broker acknowledgment.
- Lower latency but weaker delivery guarantees.

**acks=1**
- Producer waits for acknowledgment from the partition leader.
- A leader failure before replication can result in data loss.

**acks=all**
- Producer waits for acknowledgment from all currently required in-sync replicas.
- Provides stronger durability when configured with suitable replication and `min.insync.replicas`.

Tasks:

- Understand producer reliability.
- Learn the relationship between replication factor and acknowledgments.
- Understand retries and idempotent producers.
- Compare latency and durability trade-offs.

## 11. Kafka Monitoring and SRE Troubleshooting

**Objective:** Understand Kafka monitoring from an SRE perspective.

Important monitoring metrics:

**Broker metrics**
- Broker availability.
- Under-replicated partitions.
- Offline partitions.
- Request latency.
- Network throughput.
- Disk utilization.

**Consumer metrics**
- Consumer lag.
- Records consumed per second.
- Processing latency.
- Rebalance frequency.
- Offset commit failures.

**Producer metrics**
- Records sent per second.
- Request latency.
- Failed sends.
- Retry rate.
- Record error rate.

Useful commands:

```bash
# Check topic details
kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --topic pathnex-events

# Check consumer groups
kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --list

# Check consumer lag
kafka-consumer-groups.sh \
  --bootstrap-server localhost:9092 \
  --describe \
  --group pathnex-consumer-group
```

Understand how Kafka metrics can be monitored using Prometheus, Grafana and JMX-based exporters.

## 13. Real-Time SRE Troubleshooting Scenarios

**Scenario 1: Consumer lag is continuously increasing**

Investigate:

- Consumer processing speed.
- Number of partitions.
- Number of consumers.
- Broker performance.
- Consumer application errors.

**Scenario 2: Kafka broker becomes unavailable**

Investigate:

- Broker health.
- Network connectivity.
- Disk space.
- Broker logs.
- Partition leader availability.
- Replication status.

**Scenario 3: Under-replicated partitions**

Investigate:

- Broker availability.
- Network connectivity.
- Replica synchronization.
- Disk I/O.
- ISR membership.

**Scenario 4: Producer is unable to publish messages**

Investigate:

- Bootstrap server connectivity.
- Topic existence.
- Broker health.
- Authentication and authorization.
- Producer errors and retries.

**Scenario 5: Messages are not appearing in the consumer**

Investigate:

- Correct topic and partition.
- Consumer group assignment.
- Consumer offsets.
- Consumer application logs.
- Message filtering and processing logic.
