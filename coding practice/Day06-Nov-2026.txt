# Day 07 – Advanced Kubernetes Concepts & Coding Practice

## 1. Kubernetes Resource Management – Requests & Limits

Understand how Kubernetes allocates CPU and memory resources to containers.

1. Understand CPU requests and memory requests.
2. Understand CPU limits and memory limits.
3. Learn how Kubernetes schedules Pods based on resource requests.
4. Understand CPU throttling and memory pressure.
5. Understand QoS classes:
   - Guaranteed
   - Burstable
   - BestEffort
6. Understand OOMKilled and exit code 137.
7. Learn how to troubleshoot resource-intensive workloads.
8. Understand resource allocation at Pod and container levels.

**Hands-on Practice:**

Create a resource configuration:

```bash
nano resource-pod.yaml
```

Add:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: resource-pod
spec:
  containers:
    - name: nginx
      image: nginx
      resources:
        requests:
          cpu: "100m"
          memory: "128Mi"
        limits:
          cpu: "500m"
          memory: "256Mi"
```

Execute:

```bash
kubectl apply -f resource-pod.yaml
kubectl get pod resource-pod
kubectl describe pod resource-pod
kubectl top pod resource-pod
kubectl delete -f resource-pod.yaml
```

6. Understand least-privilege access.
7. Learn Kubernetes authentication and authorization.
8. Understand service account token management.
9. Learn how to audit access permissions.
10. Understand security risks associated with excessive permissions.

**Hands-on Practice:**

Create a Service Account:

```bash
kubectl create serviceaccount dev-user
kubectl get serviceaccounts
```

Create a Role:

```bash
nano pod-reader-role.yaml
```

Add:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: default
  name: pod-reader
rules:
  - apiGroups: [""]
    resources: ["pods"]
    verbs: ["get", "list", "watch"]
```

Create a RoleBinding:

```bash
nano pod-reader-binding.yaml
```

Add:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: pod-reader-binding
  namespace: default
subjects:
  - kind: ServiceAccount
    name: dev-user
    namespace: default
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

Apply and verify:

```bash
kubectl apply -f pod-reader-role.yaml
kubectl apply -f pod-reader-binding.yaml
kubectl auth can-i list pods --as=system:serviceaccount:default:dev-user
kubectl auth can-i delete pods --as=system:serviceaccount:default:dev-user
```

## 5. Kubernetes Network Policies

Understand how network traffic is controlled between Pods.

1. What is a Kubernetes NetworkPolicy?
2. Understand Ingress and Egress traffic rules.
3. Learn Pod selectors and namespace selectors.
4. Understand how to restrict communication between applications.
5. Learn default-deny network policies.
6. Understand how NetworkPolicies improve cluster security.
7. Learn the difference between Kubernetes Services and NetworkPolicies.
8. Understand CNI plugin support for NetworkPolicies.

**Hands-on Practice:**

Create a NetworkPolicy:

```bash
nano network-policy.yaml
```

Add:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-nginx-ingress
spec:
  podSelector:
    matchLabels:
      app: nginx
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              access: allowed
      ports:
        - protocol: TCP
          port: 80
```

Execute:

```bash
kubectl apply -f network-policy.yaml
kubectl get networkpolicies
kubectl describe networkpolicy allow-nginx-ingress
```

**Task:**
- Create two test applications.
- Apply a NetworkPolicy.
- Test allowed and denied traffic.
- Understand why a NetworkPolicy requires a compatible network plugin to enforce rules.

## 6. Kubernetes Probes – Application Health Monitoring

Understand how Kubernetes checks application health.

1. What is a Liveness Probe?
2. What is a Readiness Probe?
3. What is a Startup Probe?
4. Understand the difference between Liveness and Readiness.
5. Understand initial delay, timeout and probe periods.
6. Learn how failed probes affect container lifecycle.
7. Understand how readiness probes control traffic to Pods.
8. Troubleshoot containers restarting due to failed probes.

**Hands-on Practice:**

Create a probe configuration:

```bash
nano health-probe.yaml
```

Add:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-health
spec:
  containers:
    - name: nginx
      image: nginx
      ports:
        - containerPort: 80
      livenessProbe:
        httpGet:
          path: /
          port: 80
        initialDelaySeconds: 10
        periodSeconds: 10
      readinessProbe:
        httpGet:
          path: /
          port: 80
        initialDelaySeconds: 5
        periodSeconds: 5
```

Execute:

```bash
kubectl apply -f health-probe.yaml
kubectl describe pod nginx-health
kubectl get pods
kubectl get events
```

**Task:**
- Configure all three probe types.
- Simulate an application health-check failure.
- Observe Pod restarts and readiness status.
- Understand how probes help maintain application availability.

**Hands-on Practice:**

```bash

kubectl drain NODE_NAME --ignore-daemonsets
kubectl get pods -o wide
```

**Task:**

- Understand how scheduling is prevented on that node.
- Drain it and observe Pod rescheduling.
- Uncordon the node.
- Understand why PodDisruptionBudgets are important during maintenance.

Note: Perform drain exercises only in a disposable cluster with sufficient healthy nodes. Do not drain a production node without checking workloads and disruption budgets.
